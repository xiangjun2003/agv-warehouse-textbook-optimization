# AGV 仓储优化课程项目

这个仓库是一个独立的 AGV 仓储优化课程项目，使用本地 CSV 数据、自动化建模流程和我们自己实现的教材优化算法完成三个实验任务。README 的结构按照演示 PPT 的讲述顺序展开：先讲实验背景和仓库实体，再讲三个任务的实际意义、建模方式、教材算法、实验设置和结果分析。

## 1. 实验背景

自动化仓库中，AGV 负责在仓库内搬运托盘。虽然 AGV 能自动移动，但仓库系统仍然需要优化：

- AGV 数量有限，不能随意浪费空驶距离；
- 托盘分散在不同货位，取货和送货距离不同；
- 工位需要稳定供货，不能出现负载严重不均衡；
- 重点缓存或中转位置不能过度集中，否则容易形成局部拥堵。

本项目的目标是把这些真实仓库决策转化成可复现的优化模型，并使用教材中的算法用 Python 自己实现求解。

## 2. 仓库实体说明

- **AGV**：自动导引运输车，是仓库中的无人搬运资源。它从当前位置出发，到某个托盘位置取货，再把托盘送到工位或区域。
- **托盘**：承载货物的标准单元。一个托盘可以包含多个 SKU，本项目把 SKU 数量加总为托盘货量。
- **工位**：仓库或生产线中的作业位置，可以理解为拣选、包装、加工、检验或临时处理点。
- **仓库区域**：任务 2 中的区域不是固定房间，而是由模型算出来的服务范围。某些托盘货量主要分给某个工位，就形成该工位的服务区域。
- **候选货位**：任务 3 中可以被选为重点缓存或中转点的备选位置。当前实验用已有托盘/货位坐标作为候选点。

由于 AGV 通常沿仓库网格和通道移动，本项目用曼哈顿距离近似行驶距离：

```text
dist(a, b) = |x_a - x_b| + |y_a - y_b|
```

## 3. 项目内容

项目包含三个优化任务：

1. **AGV 任务分配**：决定哪辆 AGV 搬哪个托盘，并送到哪个工位。
2. **动态分区**：决定每个托盘的货量由哪些工位处理。
3. **重点缓存货位选择**：从候选货位中选出一组适合作为重点缓存或中转的位置。

这三个任务不是重复的。它们分别对应仓库运行的三个层面：当天调度、区域组织和长期布局。

## 4. 任务 1：AGV 任务分配

### 实际意义

任务 1 解决“谁去搬”的问题。

一条结果可以读成：

```text
AGV i 从当前位置出发，到托盘 j 取货，再把它送到工位 k。
```

如果分配不好，就会产生空驶、绕路和工位等待；分配合理可以降低搬运距离，提高供货稳定性。

### 建模方式

一次搬运被拆成两段距离：

```text
AGV -> 托盘
托盘 -> 工位
```

决策变量：

```text
x(i,j)：AGV i 是否服务托盘 j
y(j,k)：托盘 j 是否送到工位 k
```

目标函数：

```text
min sum d(AP) x(i,j) + sum d(PW) y(j,k)
```

其中 `d(AP)` 是 AGV 到托盘的距离，`d(PW)` 是托盘到工位的距离。

主要约束包括：

- 每辆 AGV 至多服务一个托盘；
- 托盘取货和送达保持一致；
- 工位容量有限。

### 使用算法

任务 1 先构造成线性规划松弛，用 `algorithms/primal_dual_lp.py` 中的原始-对偶内点法求解；然后用整数恢复步骤，把连续解转成可执行的 AGV-托盘-工位三元组。

### 输出结果

`results/agv_assignment.csv`：

```text
agv_index,pallet_index,workstation_index,cost
```

## 5. 任务 2：动态分区

### 实际意义

任务 2 解决“货量归谁处理”的问题。

它和任务 1 的区别是：任务 1 是车辆和任务匹配，任务 2 是托盘货量和工位匹配。模型会根据托盘位置、托盘货量和工位位置，动态形成各工位的服务范围。

### 建模方式

决策变量：

```text
z(j,k)：托盘 j 分给工位 k 的货量
```

参数：

```text
q(j)：托盘 j 的总货量
d(j,k)：托盘 j 到工位 k 的通道距离
```

目标函数：

```text
min sum d(j,k) z(j,k)
```

主要约束包括：

- 每个托盘的货量必须全部分完；
- 每个工位至少获得一定货量；
- 所有货量流 `z(j,k)` 非负。

### 使用算法

任务 2 是标准线性规划，因此直接使用 `algorithms/primal_dual_lp.py` 中的原始-对偶内点法求解。

### 输出结果

`results/dynamic_partition.csv`：

```text
pallet_index,workstation_index,quantity
```

## 6. 任务 3：重点缓存货位选择

### 实际意义

任务 3 解决“哪些位置值得重点使用”的问题。

它不是决定当天某个托盘怎么搬，而是做布局层面的选址：从已有候选位置中，挑出一批适合作为重点缓存、临时中转、工位前补货或出库前暂存的点位。

### 建模方式

决策变量：

```text
x(i) in {0, 1}：候选货位 i 是否被选中
```

选中数量约束：

```text
sum x(i) = 10
```

间距约束：

```text
x(i) + x(j) <= 1, if dist(i,j) <= 6
```

也就是说，如果两个候选点太近，就不能同时选中。模型还加入一个很小的分数项，用托盘货量近似位置价值，优先选择更有价值的位置。

### 使用算法

任务 3 使用三步：

1. `algorithms/quadratic_penalty.py`：二次罚函数法，把数量约束和间距约束变成逐渐加重的惩罚；
2. `algorithms/projected_bb_gradient.py`：投影 BB 梯度法，求解 `0 <= x <= 1` 的连续松弛问题；
3. `solve_warehouse_layout.py` 中的修复步骤：把连续解恢复成满足数量和间距要求的 0-1 选择结果。

### 输出结果

`results/warehouse_layout.csv`：

```text
pallet_index,x,y
```

## 7. 实验设置

仓库中的 CSV 数据会被统一读取成坐标、货量和距离矩阵。三个求解脚本分别构造模型，并调用对应的自实现教材算法。

仓库结构：

```text
data/                     本地仓库 CSV 数据
algorithms/               教材算法的 Python 实现
warehouse_data.py          读取地图、托盘、AGV、工位，并构造距离矩阵
solve_agv_assignment.py    任务 1：AGV 任务分配
solve_dynamic_partition.py 任务 2：动态分区
solve_warehouse_layout.py  任务 3：重点缓存货位选择
run_all.py                 一键运行三个实验
results/                  输出 CSV 结果
scripts/                  演示数据和 HTML 生成辅助脚本
```

整体流程：

```text
CSV 数据 -> 距离矩阵 -> 目标向量/约束矩阵 -> 教材算法求解 -> CSV 结果
```

## 8. 算法和任务对应关系

| 任务 | 问题类型 | 使用算法 |
| --- | --- | --- |
| 任务 1：AGV 任务分配 | 线性规划松弛 + 整数恢复 | 原始-对偶内点法 |
| 任务 2：动态分区 | 标准线性规划 | 原始-对偶内点法 |
| 任务 3：重点缓存货位选择 | 带空间冲突约束的 0-1 选择 | 二次罚函数法 + 投影 BB 梯度法 + 离散修复 |

## 9. 实验结果与分析

运行：

```bash
python run_all.py
```

典型输出为：

```text
[dynamic] status=optimal obj=79350.200
[agv] status=optimal integer_cost=131.000
[layout] status=optimal selected=10 min_dist=7
```

结果可以这样理解：

- 任务 1 输出可执行搬运安排，关注 AGV 取货和送货路线成本；
- 任务 2 输出托盘货量到工位的流向，关注距离成本和工位负载；
- 任务 3 输出分散的重点缓存/中转货位，关注布局合理性和拥堵缓解。

```bash
python -m venv .venv
source .venv/bin/activate

python run_all.py
```
